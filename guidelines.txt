Starting with the basics—these are your everyday taps that handle selection and quick actions.

Single Tap: The most fundamental interaction; users lightly touch the screen once to select items, click buttons, or open links. In apps like Spotify, it plays a song instantly. For UX polish, add subtle ripple effects or haptic feedback to make it feel tactile.
Double Tap: Two quick taps in succession, often for zooming in on images or maps (e.g., Google Maps) or liking posts (Instagram). It amps up interactivity by layering actions on the same spot.
Long Press (Tap and Hold): Holding a finger down for a second or so triggers context menus, drag modes, or previews. Think holding a message in WhatsApp to react or delete—perfect for power users without cluttering the UI.

Now, moving to directional movements—these keep users scrolling and navigating fluidly, turning static screens into dynamic flows.

Swipe (Up/Down/Left/Right): Sliding a finger across the screen to scroll lists, switch tabs, or dismiss notifications. Vertical swipes power infinite feeds in Reddit, while horizontal ones (like Tinder's left/right) make decisions fun and addictive.
Flick: A fast swipe that continues with momentum, like flinging through a photo gallery in Apple's Photos app. It adds physics-based realism for that premium inertia feel.
Edge Swipe: Swiping from the screen's edge, often for system navigation like going back (Android's gesture nav) or revealing side menus. In your app, use it for quick access drawers without buttons.

Then we have multi-finger gestures—these unlock zooming and manipulation, making apps feel expansive and controllable.

Pinch (Close): Bringing two fingers together to zoom out on maps or photos (e.g., Pinterest boards). It's essential for content-heavy apps to let users overview quickly.
Spread (Open): Spreading two fingers apart to zoom in—pairs perfectly with pinch for intuitive scaling in design tools like Figma mobile.
Rotate: Twisting two fingers to rotate images or objects, common in photo editors or games. Adds a playful, hands-on vibe.
Two-Finger Swipe/Scroll: Using multiple fingers for secondary actions, like scrolling with two fingers in browsers to avoid accidental selections.

Finally, some advanced or device-specific features that elevate UX to pro levels, especially in trendy apps.

Drag and Drop: Pressing and moving an item to rearrange (e.g., iOS home screen icons or Trello's cards). Combine with long press for seamless editing modes.
Pull to Refresh: Pulling down on a list to reload content—iconic in Twitter/X feeds, with satisfying animations like spinning loaders.
Shake: Physically shaking the device to undo actions or trigger events (e.g., undo typing in Notes). It's gimmicky but memorable if used sparingly.
Force Touch/3D Touch (or Haptic Variants): Pressing harder for previews (peek/pop in iOS Mail), though now often simulated with long press on Android. For modern twists, use haptics for "deep press" feedback.
Hover (with Stylus or Finger Proximity): Rare for pure touch, but in apps like drawing tools, it previews actions before committing.

General SolidJS Security Mistakes (with Firebase Integration):

Do not use dangerouslySetInnerHTML in SolidJS components for rendering Firebase-fetched data, as it exposes your app to XSS attacks from unsanitized user content.
Do not skip server-side validation of Firebase API responses in SolidJS; relying solely on client-side checks (e.g., in effects) allows bypassing via dev tools.
Do not fail to sanitize inputs from Firebase auth forms in SolidJS; use libraries like DOMPurify instead of raw signal updates to prevent injection.
Do not neglect CSRF protection in SolidJS forms submitting to Firebase Functions; avoid token-less POSTs that can be forged cross-site.
Do not store Firebase auth tokens directly in SolidJS signals without encryption; expose them insecurely via localStorage without additional safeguards like HttpOnly cookies.
Do not mutate auth state stores directly in SolidJS when handling Firebase onAuthStateChanged; always use functional updates to avoid reactivity loss and potential leaks.
Do not ignore rate limiting in SolidJS effects calling Firebase APIs; unchecked loops can lead to DoS vulnerabilities and billing spikes.
Do not embed Firebase API keys as secrets in SolidJS client code; treat them as public but never rely on them for access control.

Firebase Authentication Pitfalls:

Do not use anonymous authentication as a permanent replacement in SolidJS apps; allow it for non-public data writes without forcing conversion to verified methods like email/MFA.
Do not assume Firebase Auth alone secures your SolidJS app; skip enforcing role-based checks via custom claims, leading to unauthorized access.
Do not disable email enumeration protection in Firebase Auth for SolidJS logins; expose endpoints to brute-force guessing of user accounts.
Do not mint custom JWTs client-side in SolidJS; handle them insecurely without server-side verification to prevent token forgery.
Do not skip upgrading to Google Cloud Identity Platform for MFA in high-security SolidJS apps; rely on single-factor auth in 2025 where multi-factor is standard.
Do not hardcode admin roles in SolidJS based on emails (e.g., in context providers); avoid custom claims for robust RBAC.

Database (Firestore/Realtime) Security Issues:

Do not leave default open access rules in Firestore or Realtime Database for SolidJS integrations; start with deny-all and add rules post-development.
Do not write Firestore security rules as an afterthought in your SolidJS project; treat them optionally instead of as a core schema.
Do not pull entire collections via .get() in SolidJS resources; fetch unnecessary data, exposing more than needed and risking performance-based DoS.
Do not overuse .onSnapshot() for real-time updates in SolidJS effects; subscribe to non-essential data, leading to excessive reads and potential data leaks.
Do not store large nested objects or arrays in single Firestore documents queried from SolidJS; exceed size limits and complicate rule enforcement.
Do not perform client-side joins on Firestore data in SolidJS; denormalize insecurely, risking inconsistent access controls.
Do not skip unit testing Firestore rules with emulators before deploying SolidJS apps; deploy unvalidated rules that allow unauthorized writes.

Storage Security Anti-Patterns:

Do not expose full Storage buckets without rules in SolidJS file upload components; allow public writes/uploads without auth checks.
Do not limit data exposure by not splitting collections (e.g., public vs. private) in Storage rules for SolidJS apps; mix sensitive files openly.
Do not neglect Firebase App Check for Storage access from SolidJS; allow unauthorized apps to request files without attestation.
Do not use weak conditions in Storage rules matching SolidJS user roles; define vague patterns that fail to deny malicious requests.

Cloud Functions Security Blunders:

Do not store sensitive credentials in environment variables for Functions called from SolidJS; reuse them across invocations without Secret Manager.
Do not deploy untested Functions directly to production from SolidJS integrations; risk self-DoS via infinite loops without emulator testing.
Do not process real-time results without batching in Functions; expose to abusive traffic from SolidJS clients without Pub/Sub limits.
Do not ignore concurrent instance limits on Functions; allow spikes from SolidJS API calls to escalate costs during attacks.

UX/UI Security Anti-Patterns for 2025 Trends (with Tailwind CSS):

Do not design login forms in SolidJS with Tailwind without accessibility checks; use low-contrast colors (e.g., gray-on-gray in neubrutalist styles) that fail WCAG, indirectly leaking data via poor usability.
Do not implement excessive animations in Tailwind-styled auth UIs; hinder performance on mobile, leading to timeouts that expose partial data.
Do not ignore dark mode adaptations in Tailwind for Firebase error messages; display sensitive info (e.g., "invalid token") in unreadable contrasts.
Do not use non-responsive Tailwind classes in SolidJS login views; create mobile-unfriendly designs that encourage insecure workarounds like zooming.
Do not skip consent modals in minimalist 2025 UX for Firebase data collection; collect user data without clear, glassmorphism-styled prompts, violating privacy trends.
Do not over-rely on client-side masking of sensitive data in Tailwind UIs; display redacted info without server enforcement, risking exposure.
